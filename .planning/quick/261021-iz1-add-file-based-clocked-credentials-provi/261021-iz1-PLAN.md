<objective>
Make the Clocked API key readable from a per-user credential file so GUI-launched hosts (Claude Code desktop, OpenCode background service) work without machine-wide env vars, and add `bashboy auth set|status|clear` to manage that file safely.

Purpose: today the key can only come from an environment variable. Shell-profile env vars are invisible to GUI-spawned hosts, and `setx` leaks the key to every process on the machine. A 0600 file under the user profile fixes both without putting a secret in `config.toml` (which is shareable and pasted into issues).

Output: new `src/bashboy/credentials.py`, `resolve_api_key()` + `ProviderConfig.api_key_file` in `config.py`, `auth` subcommands in `cli.py`, offline tests covering BRIEF.md §Test matrix (10 cases), updated README, version 0.2.0.
</objective>

**1. `src/bashboy/credentials.py` (new).** Stdlib only (`os`, `stat`, `sys`, `pathlib`, `dataclasses`, `subprocess`). It must NOT import `.config` (config imports this module; a reverse import is a cycle).

- `_is_windows() -> bool` = `os.name == "nt"` — module-level so tests can monkeypatch it.
- `_warn(msg)` does a **lazy** `from .classify import log` then `log(msg)`. Lazy because classify → config → credentials is already loaded at call time; a module-level import would be circular. Brief D-04 locks the warn-only Windows behaviour to this helper, so warnings surface only when `BASHBOY_DEBUG` is truthy — that is intentional.
- `permissions(path)`:
  - not `path.is_file()` → `PermissionState("missing", f"{path} does not exist")`.
  - Windows: `extra = _windows_extra_principals(path)`; `None` → `("unverified", "could not verify the file ACL")`; `[]` → `("owner-only", "owner-only ACL")`; non-empty → `("extra-principals", "ACL grants access to: " + ", ".join(extra))`. Never raise, never refuse.
  - POSIX: `mode = stat.S_IMODE(path.stat().st_mode)`; `mode & 0o077` → `("insecure", f"mode {mode:04o} is readable by other users; run `chmod 600 {path}`")`; else `("owner-only", f"mode {mode:04o}")`.
- `read_token(path)`:
  - read at **call time**, never cached (D-05: rotation must not need a host restart).
  - `FileNotFoundError`/`IsADirectoryError` → `None`.
  - POSIX: if `stat.S_IMODE(...) & 0o077` → raise `CredentialPermissionError(f"refusing to read {path}: mode {mode:04o} is readable by other users; run `chmod 600 {path}`")`. Failing closed beats consuming a leaked secret (D-03).
  - Windows: if `_windows_extra_principals(path)` returns a non-empty list → `_warn(...)` naming the principals, then continue (D-04: warn only).
  - Decode UTF-8 with `errors="replace"`, `.strip()`; empty → `None`. Strip a leading `KEY=` only never — the format is a bare token (D-02).
- `write_token(path, token, *, overwrite=False)`:
  - `token = token.strip()`; empty or containing `"\n"`/`"\r"` → `CredentialError("token must be a single non-empty line")`.
  - `if path.is_file() and not overwrite:` → `CredentialExistsError(f"{path} already exists; re-run with --force to overwrite")`.
  - create parent: capture `created = not path.parent.exists()`, `path.parent.mkdir(parents=True, exist_ok=True)`, and if `created and not _is_windows()` → `os.chmod(path.parent, 0o700)` (D-08: `~/.bashboy` is 0700). Only chmod a directory we created — never tighten a user-chosen `--file` directory such as `$TEMP`.
  - lazy `from .installers import atomic_write_text` (keeps `bashboy check` startup free of `tempfile`), write `token + "\n"` atomically, then `os.chmod(path, 0o600)` on POSIX best-effort (`except OSError: pass`). On Windows leave attributes alone.
- `clear_token(path)`: `path.unlink()`; `FileNotFoundError` → `False`; else `True`.
- `_windows_extra_principals(path) -> list[str] | None`: run `subprocess.run(["icacls", str(path)], capture_output=True, text=True, timeout=5)`; return `None` on `OSError`/`subprocess.SubprocessError`/non-zero exit (unknown, so warn "could not verify"). Parse each output line: strip; skip blanks; first line is `<path> <PRINCIPAL>:(...)`, continuation lines start with the principal; take the token containing `":("`, split it into principal and parenthesised rights. Keep only lines whose rights contain a bare `F`, `M`, or `W` grant. Skip principals that are the current user (`os.environ.get("USERNAME","").lower()`, compare case-insensitively on the part after `\`), and skip `SYSTEM`, `NT AUTHORITY\SYSTEM`, `ADMINISTRATORS`, `BUILTIN\ADMINISTRATORS`, `CREATOR OWNER`, `OWNER RIGHTS`, `*S-1-5-18`, `*S-1-5-32-544`. Return a sorted deduped list. Rationale for `subprocess` here: `os`/`stat` cannot read ACLs and a ctypes `GetNamedSecurityInfo` implementation is ~100 lines of blind pointer work; `icacls` is a Windows built-in, so this adds no dependency, and the whole path is warn-only.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell → `bashboy auth set` | The token enters the process; if it came from argv it would land in shell history and process listings |
| filesystem → `read_token` | The credential file is attacker-writable if permissions are loose; a leaked secret would be silently consumed |
| config file → key resolution | `config.toml` is shareable/pasted into issues; a token must never live there |
| `auth set` → Clocked endpoint | The freshly saved token is sent once for validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-iz1-01 | Information disclosure | `auth set` token input | mitigate | Accept only `getpass.getpass` or `--stdin`; no `--token`/positional argument exists in the parser. Stdin path exists for CI/provisioning. |
| T-iz1-02 | Information disclosure | stdout/stderr/`config show`/exceptions | mitigate | Never interpolate the token into any print, log, `Classification.reason`, or exception; tests assert the sentinel token appears in no captured output. `log()` is only ever passed source labels. |
| T-iz1-03 | Elevation of privilege | POSIX credential file mode | mitigate | Refuse to read when `mode & 0o077`; raise `CredentialPermissionError` naming `chmod 600 <path>`; `classify_command` converts that into deny/fallback (fail closed). Write 0600 + parent 0700. |
| T-iz1-04 | Information disclosure | Windows ACL inheritance | accept | Warn-only by design (BRIEF D-04): hard refusal on inherited ACLs would be a support nightmare, the file lives under the user profile whose default ACL is owner-only, and the probe is best-effort. Warning surfaces via `log()` under `BASHBOY_DEBUG`. |
| T-iz1-05 | Tampering | partial/crashed credential write | mitigate | Reuse `installers.atomic_write_text` (same-dir tempfile + `os.replace`), then chmod; a crash cannot leave a truncated token that would produce confusing auth failures. |
| T-iz1-06 | Spoofing | `BASHBOY_API_KEY_FILE` env override | accept | Env vars are already trusted input in this project (`BASHBOY_CONFIG`, `BASHBOY_ENDPOINT`); anyone who can set env vars in the agent's shell can also set `CLOCKED_API_KEY`. Documented in the precedence table. |
| T-iz1-07 | Information disclosure | config file | mitigate | Only the *path* is stored in `[provider].api_key_file`; `DEFAULT_CONFIG_TOML` and `config show` never carry a token. |
| T-iz1-08 | Denial of service | unreadable/format-broken credential file | accept | Missing/empty → no key → deny/fallback with an actionable reason. A malformed credential file degrades to a closed verdict, never an allow. |
| T-iz1-09 | Repudiation | `auth clear` deleting the wrong file | mitigate | Print the resolved path before/after; require interactive confirmation unless `--force`; missing file is a no-op. |

Residual risk: the token is briefly present as a Python `str` in memory (unavoidable), and Windows ACL verification is advisory. Neither changes the fail-closed policy, the binary verdict, or the deny-only host integrations.
